Judged the way a browser would

A header scanner is only useful if you can trust a red line. mamori reports what the browser actually enforces on the response it actually got.

Missing is not weak

A header that isn't set and a header set to a value that does nothing are different problems. mamori reports them as missing and weak, and a weak finding says which value is the problem.

No findings for ignored headers

HSTS is only judged on HTTPS responses. X-Frame-Options is withheld when CSP declares frame-ancestors. Cache-Control only matters once a cookie is set.

After the redirects

Findings are judged on the final response. If https:// redirects down to plain http://, that is a high severity insecure finding, and the report names the URL it landed on.

Made to gate a pipeline

Run it as a GitHub Action or as a plain binary. Findings land in the repository's Security tab as SARIF, and the exit code tells CI what happened without parsing output.

.github/workflows/scan.yml
permissions:
  security-events: write

steps:
  - uses: PhyberApex/mamori@{{ action_ref }}
    with:
      targets: |
        https://example.com
        https://example.org
      fail-on: high
      upload-sarif: true
.mamori.yaml
rate: 2
baseline: ./previous-scan.json
suppressions:
  - host: https://legacy.example.com
    reason: migration tracked in JIRA-456
    expires: 2026-12-31

Fail on what matters

-fail-on low|medium|high sets the bar. Exit 1 means findings tripped it, 2 a usage or config error, 3 a failed hook, 4 an interrupted scan.

Gate on what changed

Save a scan with -o json and pass it back as -baseline. Findings already in it are marked known and stop failing the build, so you can adopt mamori on a codebase that isn't clean yet.

Accepted risk that expires

A suppression carries a reason and an optional expiry date. The finding stays visible in every report, and once the date passes it gates again.

Considerate towards the thing it scans

  • -workersTargets are scanned concurrently, ten at a time by default.
  • -rateCaps requests per second to any single host, shared across the whole scan.
  • -HAdds request headers, for endpoints behind auth.
  • User-AgentEvery request identifies itself as mamori/{{ site.mamori_version }}, so you can allowlist it in a WAF.
  • -pre-scan-hookRuns a command before and after the scan, for example to pause and restore a WAF rule.
  • -oTerminal, newline-delimited JSON or SARIF 2.1.0.

Install

A single binary or a container image. Pick whichever fits where you scan from.

  • Go

    $go install github.com/PhyberApex/mamori/cmd/mamori@latest

  • Docker

    $docker run --rm ghcr.io/phyberapex/mamori:latest https://example.com

  • Binary

    Linux and macOS builds for amd64 and arm64 are attached to every release.

Then point it at something

$mamori https://example.com https://example.org

Flags, environment variables and the config file are documented in the README.
